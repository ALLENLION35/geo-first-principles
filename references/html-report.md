# HTML 报告：让负责人看懂，保留完整分析，快速成稿

默认交付一份可直接打开、连续滚动的单文件 HTML。桌面左侧为常驻分级目录，正文按章节与小节自然展开；手机用目录按钮打开导航，点击后回到对应正文。用户另有格式要求时按其要求；不能创建文件时说明限制，并先交付同样完整的可读内容，不把源码当成报告。

## 每个模块先给读者一个明确判断

六个主体章节、最终结论与数据来源各有一句醒目的核心金句。独立展开的十步要点也各有一句，可直接承接标题中的大白话，正文不重复解释一遍。

金句须表达**本企业的关键判断与业务价值**，由该模块正文支持。用具体的客户、问题、选择或行动，讲清为什么重要；不能只是“本章讲竞争格局”，也不能把待验证的机会说成已经发生的效果。通常一到两句读完，条件不可删。

例：

- 行业章节：批发商愿意为账货衔接付费，功能多不代表适合他当前的生意。
- 价值章节：AI 若能帮合适客户从了解走到演示，才有扩展价值；当前还不能据此扩大获客预算。
- 行动章节：先把业务和上线责任讲成一份能共用的资料，再按实测安排后续内容。

这些是虚构示例的表达演示。真实报告必须重写，不能固定套这几句话。

阅读顺序为：**结论式金句 → 事实与因果推导 → 取舍、成立条件及行动含义**。这只是阅读顺序，不要求每章重复增加三套小标题或三张卡片。保留六部分原有任务，第六部分金句之后仍按原定五块顺序展开。

## 完整性优先于版式

逐模块保留：客户为何买与替代方案、可比竞争证据、购买路径与关键停顿、GEO 的价值链和投入取舍、场景与五类问题的主次、五题原文及操作记录、十步完整介绍与本企业适用步骤、动作负责人和完成标准、工具交接、六标签最终结论、数据与来源。

不能为了卡片等高、控制屏数、减少文件大小，删掉依据、关键数字及口径、反向情况、优先级理由、成立条件或来源。长段按意思拆开；同一件事只在最适合的位置写全。允许页面自然变长，不设置总字数上限。

所有关键内容默认展开；不用折叠面板、分页、轮播、弹窗或点击后才加载的正文。不限制正文高度、不截断溢出、不省略表格行列。宽表放可横向滚动的容器，保留可发现的提示；不缩小到无法阅读。来源紧跟判断，文末再集中列目录。

## 让语言更容易懂

对外写“客户问题组”，不写“意图簇”；写“内容任务说明”，不写 Brief；写“先做／配合／后续”，不写 P0/P1/P2；写“咨询和成交记录”，不凭空引入 CRM。规范中的内部分析用语不直接搬进报告。

十步名称保留与开源体系的对应关系，首次在旁边配大白话。例如“事实本体：整理企业真实资料”“基线检测：记录 AI 现在怎么回答”“效果归因：核对咨询和成交从哪里来”。不要假定负责人了解缩写，也不要用解释术语代替经营分析。

## 复用模板，内容只写一次

模板为 `assets/report-template.html`：暖白纸感背景、米色左侧栏、细分隔线、橙色导航高亮与绿色核心判断；系统字体，正文 17px，手机正文 16px。桌面正文随侧栏偏移，保持适合长文的阅读宽度。章节不使用厚黑框或重投影；小节通过间距、轻卡片与标题区分。无在线字体、外部脚本、图片素材下载或前端构建依赖。单页正文已经写入 HTML，关闭 JavaScript 仍能读全文、查看来源、手选复制五题；小段脚本增强目录抽屉、当前章节高亮、阅读进度、复制与打印；阅读进度只表示页面滚动位置，不代表理解程度。

**能运行 Python 3.9+：优先让模型只写一次报告正文，直接调用本地渲染器。** 不读取渲染器或整份模板源码来仿写，不先输出一遍对话全文再输出一遍 Markdown 再重写 HTML。无需为渲染安装任何第三方库。

```bash
python3 scripts/render_report.py report.md -o 企业GEO分析.html
```

上面路径相对本技能目录；宿主实际调用时定位本技能文件，不假定当前工作目录。`report.md` 是本轮完整正文的中间文件，企业默认收到 HTML。本地程序只排版，不联网、不运行模型、不改变分析结论。

正文使用常见 Markdown：一个 `# 总标题`；六部分、最终结论、数据与来源用 `##`；需要的小标题用 `###`、`####`；表格、列表、链接、粗体、引用块正常写。每个主模块开头加：

```markdown
> **本章金句**：此处写该企业有依据的核心判断。
```

十步要点的小标题后用 `> **金句**：...`，渲染为较轻的橙色提示。五题标题使用 `**问题1｜业务疑问短名**`，下方普通引用块放完整问题，程序自动加复制按钮。不要给金句或题目加其他隐藏标记。表格中的换行可用 `<br>`；单元格内竖线写 `\|`。其他原始 HTML 不用于这一路径。

十步图可以用下面的小数据块，由程序生成可随屏幕换行的十步路线。所有状态从第三部分已经作出的决定取得；示例里的范围不是默认答案。没列出的步骤显示“本轮暂不安排”，起点可写 `null`。

```geo-route
{"start":1,"active":[1,2,3,4,5],"conditional":[6,7],"rhythm":[8,9,10],"condition_label":"等第 4 步结果后启动"}
```

简单客户路径可用 `geo-funnel` 数据块；每个条目含 `label` 和 `note`。例如 `[{"label":"产生需求","note":"人数未记录"},{"label":"咨询","note":"人数未记录"}]`。按实际路径填写，不套示例步骤，不填无依据人数；程序用等宽阶段条，明确标为路径示意。详细原因仍保留在阶段表或正文，不由图代替。

**不能执行脚本但能生成文件：直接复用模板。** 填入总标题、背景与核心判断、目录、各模块的 HTML 正文；保留模板 CSS 和已有小脚本，不从头设计页面。不强制先写 Markdown。把标题用于 `TITLE_TEXT` 时作 HTML 转义；正文使用正常的语义标签。左侧目录由主模块和实际小节组成，每个链接指向唯一的正文锚点；保留移动目录、复制与打印脚本，以及无脚本时的可读回退。十步用有状态文字的编号网格，或现有 SVG 加可读状态说明。渲染器生成的结果与直接 HTML 路径应包含同一套完整内容。

**只有 SKILL.md：** 使用主文件中的轻量单页要求直接生成 HTML，无需补装渲染器。若宿主无法交付 HTML 文件，先交付完整的可读报告并说明能力限制。

## 用轻量图示减轻阅读负担

优先在六个主模块里，将正文已有的角色关系、客户路径、收入与成本、重点客群、操作顺序和行动路线转成简明图示。选择能帮助理解的关系，不为了数量凑图；主模块金句仍放在图示之前。图示作概览，完整依据、表格与操作正文继续保留。没有同口径数据时用等宽卡片或步骤图，不画暗示比例、权重或效果的柱高、面积与百分比。

可复用两种小数据块，均由标准库渲染器直接生成，无图表库、图片生成或外部资源。`geo-cards` 表示并列卡片，`geo-flow` 表示有顺序的步骤；每项必须含文字 `label` 与 `text`，可选 `value` 仅呈现正文已经支持的数字与单位。`note` 保留范围、假设或来源链接，禁止删掉重要条件以放大数字。数据块中也可用普通 Markdown 链接与强调。

````markdown
```geo-cards
{"title":"选择前要核对的条件","items":[{"label":"产品适配","text":"说明本企业能够服务的需求与边界。"},{"label":"交付准备","text":"说明客户与企业分别要准备什么。"}],"note":"请替换为当前报告正文已有依据的结论，不新增事实。"}
```
````

顺序图使用相同字段，将类型改为 `geo-flow`，每项是一项已确定的动作或路径阶段。数字卡片保留单位、时间范围和成本口径；示例中的 8,000 元差额不等于 GEO 净收益，不可改写为收益 KPI。

目录应显示六个主模块、最终结论、数据来源；有小节时生成二级跳转，展开的十步也应能直接定位。小节目录只是入口，不折叠正文。复制五题、来源锚点和完整表格都继续工作。不要照搬版式参考的行业内容、人物、照片、记录笔记功能或无关工具栏。

## 快速校验，不为装饰反复等待

研究完成后只生成一次正文、排版一次；发现遗漏或错位，只修相应段落和样式，不重复联网研究。常规交付检查：侧栏与小节跳转正确、各锚点唯一、手机目录可开关、六部分齐全、主模块与展开步骤有具体金句、恰好五题可复制、来源可点击、数字与条件完整、宽表可滚动、占位符已替换。工具可用时看一次桌面和手机预览；不为微小装饰反复截图，不生成 PDF、图片版或网页应用，除非用户要求。

速度优化针对重复写作、模板代码和渲染工作，不能减少关键核验与分析。不要把本地排版耗时称作整份报告的生成耗时，也不要承诺固定分钟数。

维护模板时可运行 `python3 scripts/render_report.py --example -o preview.html`，只对随包虚构案例做样式预览；不启动真实企业诊断。示例输入作为可跳转的来源附在预览末尾，不需要每次真实运行都读取该长例。
